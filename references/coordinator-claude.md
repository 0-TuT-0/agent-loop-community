# Claude 总控专用：通信与监视

本文件只给 Claude Code 担任的总控读。与引擎无关的规则在其他文件里；这里写的是 Claude 总控特有的做法：用 `SendMessage` 和 `ListAgents` 通信，自己挂后台监视。

## 身份登记

照 [session-identity.md](session-identity.md) 登记：开发计划顶部一行 `- 总控会话：<当前名称>（sessionId：<id>，更新于 <时间>）`。开 Claude 窗口时把这一行的名称和 sessionId 写进初始提示的「总控会话」，窗口据此发消息提前通知。

没有通过 `agent-loop start <功能名>` 启动时，总控这一行不会自动进票台账，启动后补一次：`agent-loop window register --step coordinator --session <自己的 sessionId>`。

## 收通知

完成的信号有两路，以文件为准：

- **文件**：票头 `Status`、产物末尾的完成标记，由监视发现；
- **消息**：Claude 窗口用 `SendMessage` 提前通知，可能因为窗口中断或电脑休眠而发不出来。

两路先后到达同一件事时，后到的那次先查进展记录：这张票已经合入、或者下一个窗口已经开过，就不再处理。

## 挂监视

用后台 Bash（或 Monitor 工具）运行：

```
agent-loop watch wait --restart --feature <功能名>     # 启动、恢复、接手时的第一次
agent-loop watch wait --feature <功能名>               # 之后每次处理完重挂
```

**启动、恢复、接手时一律重启监视**（加 `--restart`）：它先停掉这个功能上别的监视，再开始等。上一个总控留下的监视可能还挂在旧会话上（你永远收不到它的唤醒），也可能是 Codex 的常驻监视。重启只换进程，「哪些事已经通知过」的记录保留，所以不会重报，交接期间发生的变化也不会漏。

它盯着功能目录，等待期间不消耗 token，**没有时限**：没有变化就一直等，不会为了「没有变化」唤醒你。有变化时把通知打印出来并退出，你被唤醒；每行一条，例如 `[agent-loop 监视] p1/issues/03-x.md 的票头变为 done`。

- **盯什么**：功能目录下所有票的票头、各类完成标记、可选窗口留的 `【待总控处理】`、送出后迟迟没被接收的裁决、开了窗却没开始的窗口（[ticket-file-windows.md](ticket-file-windows.md)「监视」）。它自己找目标，不用你列。按时间提醒的事它自己计时，到点照样唤醒你。
- **处理完之后重挂**：不加 `--restart` 的那条命令再运行一次。哪些事已经通知过记在文件里，同一个状态只通知一次，所以不用告诉它哪些处理过了。还没处理完的 `【待总控处理】` 条目不会重复通知；处理完把标记改成 `【总控已处理 …】`。
- **第一次运行**：把当时的状态记成已知，不为已经发生的事补发通知。开第一个窗口之前命令会自动做这一步，所以窗口写下的东西不会被漏掉。
- **它结束了就是有事**：处理完重挂。后台任务意外结束时你同样会被唤醒，输出里没有通知，直接重挂。你重启或恢复之后用 `--restart` 重挂一次：你不在的时候发生的变化，这时会一次报出来。
- **开窗之后直接回来等**：不要自己挂一个检查去看窗口启动了没有。窗口三分钟没开始，监视会通知你（[ticket-file-windows.md](ticket-file-windows.md)「窗口有没有开始、还在不在」）。
- **忘了挂时命令会提醒**：开窗或送消息之后，如果监视没有挂着，命令的输出末尾会说明并给出要运行的命令。
- **同一时刻只挂一个**：已经有一个在等时，再挂的那个会说明并退出。

## 把裁决送回窗口

裁决写进票的 Comments 之后：

- **Claude 窗口**：用 `SendMessage` 告诉它「裁决 <n> 已写入，请读取后继续」，然后运行 `agent-loop watch expect <票> <n>` 登记「等待接收」。按 [session-identity.md](session-identity.md)「找其他窗口」确认对方的当前名称。
- **Codex 窗口**：`agent-loop send <票> "裁决 <n> 已写入票的 Comments，请读取后继续" --expect <n>`，命令会同时登记「等待接收」。

五分钟后票头仍是 `needs-decision`，监视会报「裁决 <n> 未被接收」：重送一次并重新登记；再次收到未被接收的通知时，告诉用户，请用户在那个窗口说「继续」。

`SendMessage` 发不出去、或者找不到对方时，运行 `agent-loop window list`：标签页已经不在的窗口会被登记为关闭并列出来，这件事还要继续就重开窗口。Codex 窗口不用另查，`agent-loop send` 送之前自己会确认。

## 让窗口返工一份已经写过完成标记的文件

例如请测试文档窗口修订测试计划、请审计窗口补充报告。同一个完成标记监视只通知一次，所以返工之前要登记，否则窗口改完了你不会被唤醒：

- **Claude 窗口**：先运行 `agent-loop watch redo <文件>`，再用 `SendMessage` 说明要改什么，并请它先删掉文件末尾的完成标记、全部改完再写回。
- **Codex 窗口**：`agent-loop send <窗口编号> "<要改什么>" --redo <文件>`，命令会登记并把那句话附在消息后面。

文件内容变了、末尾又有完成标记时，监视再通知一次。

票头已经是 `done` 的票要返工时同样要登记：Codex 的开发窗口用 `agent-loop send <窗口编号> "<话>"`，命令自动登记；Claude 的开发窗口先运行 `agent-loop watch redo <票>`，再用 `SendMessage`。

## 给其他窗口发消息

要改变一个在途窗口的做法（例如收紧权限）时：Claude 窗口用 `SendMessage`；Codex 窗口先把内容写进票的 Comments，再用 `agent-loop send <窗口编号> "<话>"` 提醒它去读（一张票只开着一个窗口时也可以写票号；开着两个以上时命令会拒绝并列出窗口）。
