# 数据库与共享环境

参数文件开启「会话不连库」这条护栏时适用（默认开启）。**所有库表变更都以脚本交付，由用户手工执行。** 会话的职责是写出脚本，并说明执行方式。脚本目录、命名、文件头格式见参数文件和项目规范。

## 会话的边界

- 会话只交付脚本文件。连接数据库、建库建表、写数据、执行脚本，都由用户完成。
- 共享环境上的其他写操作（改配置、改开关、调写接口）同样由用户完成，或者由用户逐项确认后执行。
- 脚本的正确性靠代码审查和测试保证。会话不为了验证脚本去安装数据库客户端或容器。

## 脚本约定（项目没有另外规定时）

- 位置与命名：`<脚本目录>/YYYYMMDD_<说明>.sql`。日期取编写当天，说明用英文小写，单词之间用下划线连接。
- 只读核查脚本另建 `YYYYMMDD_<说明>_check.sql`，里面只有 SELECT。
- 文件头注释写明：
  - 目的；
  - 执行顺序（先执行脚本再部署，还是先部署再执行）；
  - 依赖的脚本；
  - 能否重复执行；
  - 执行环境；
  - 怎么回退。
- 共享的基础数据（资源码、字典等）只追加，不改动已有行。

## 测试

测试不连接真实数据库。依赖新表的代码，通过 mock 数据访问层来测试。脚本本身需要校验时，用读取脚本文本的测试来断言。

## 回报

开发票的完成回报中，列出本票新增的每个脚本：文件路径、执行顺序、执行环境，以及「需要用户手工执行」的提示。下一张票依赖这些脚本已经执行时，在回报里明确写出。总控在用户确认执行之前，不开依赖这些脚本的票。

## 只有上游能提供的能力

需要的信息或能力只有外部依赖方（参数文件「外部依赖方」）能提供时，登记为外部需求，交给用户去沟通。在相关票的 Comments 里写明四项：需要什么；本地为什么做不了（核对过哪些现有接口）；支撑哪个功能；对方提供之前怎么降级。并在回复里明确提示用户：这一项需要你去沟通。
