# 讨论阶段：多窗口 grilling

一张 `/wayfinder` 地图由多个会话窗口并行推进：总控画地图，模块窗口各自认领一张票，用 grilling 和用户讨论。

## 角色

- **总控**：画地图，处理跨模块冲突，新建跨模块票。frontier 和 Not yet specified 都清空后，运行 `/to-spec` 汇总，再按阶段写开发计划。模块票交给模块窗口认领，总控不替模块讨论。
- **模块窗口**：一个会话认领并解决一张票；解决后开新会话接下一张。

## 把进行中的单窗口讨论拆成地图

用户已经在一个窗口里讨论了一部分（问题编号可能不连续）时：
1. 让那个窗口把已有结论按主题归组，写成地图的 Decisions so far，并注明来源问题编号。
2. 把还没讨论的问题按模块拆成票，写明每张票依赖哪些已有结论（`Blocked by`）。
3. 那个窗口改做总控，或者把地图交给新的总控。

## 工作目录

讨论阶段，所有窗口都开在同一个主工作树里，共享同一份任务目录、`GLOSSARY.md`、`docs/adr/`。worktree 会给每个窗口一份独立副本，切断共享，所以讨论阶段不用 worktree，只在开发阶段用。

## 协作规则

模块窗口和总控都遵守：

- 每轮提问前，重读地图的 Decisions so far 和 `GLOSSARY.md`，吸收其他模块的最新决定。
- 本模块的决定影响其他模块（接口、数据归属、术语、依赖顺序）时：先在受影响票末尾的 `## Comments` 追加说明，再用 `SendMessage` 通知对应的模块窗口和总控。
- 两个模块的决定冲突时：通知总控，由总控新建一张跨模块 grilling 票，把冲突交给用户裁决。
- 写地图或 `GLOSSARY.md` 之前先重读，只追加或修改自己负责的行。
- 模块窗口认领票时，在票头 `Status:` 行下加 `Session: <名称>（sessionId：<id>）`，并通知总控；票解决后，把结论要点和受影响的票回报给总控。
- 讨论阶段只写任务目录、`GLOSSARY.md`、`docs/adr/`。
- 同时开着的模块窗口建议不超过 3 个；参数文件填了窗口上限时以它为准。

## 收敛之后

1. 总控运行 `/to-spec` 汇总整张地图。
2. 和用户一起把汇总结果切成阶段，写成开发计划：[dev-plan.md](dev-plan.md)。
3. 进入第一个阶段：[dev-phase.md](dev-phase.md)。
