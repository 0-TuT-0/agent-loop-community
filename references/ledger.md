# 票台账

票台账记录每张票和每个窗口的事实，用来事后回看：哪个模型做的票返工多、裁决多、审计问题多，各环节花了多少 token。它和开窗清单是两样东西：开窗清单回答「现在该做什么」，票做完就从里面消失；票台账里的行永久保留。

台账由 `agent-loop` 命令生成，总控只运行命令，不编辑台账文件。数据在 `<功能目录>/ledger/`，给人看的表是 `<功能目录>/ledger.md`。

## 内容与来源

| 内容 | 来源 | 谁来记 |
| --- | --- | --- |
| 开窗时间、票、环节、模型、会话 ID | 开窗时确定 | `agent-loop window open` 自动记 |
| 风险 | 票头 `Risk:` | 命令读票文件 |
| 裁决次数 | 票的 Comments 里「### 裁决 n」的个数 | 命令数 |
| 用量 | 窗口的会话记录 | 命令汇总 |
| 完成时间、返工、计划修改、审计问题、修复票的来源票 | 需要总控判断 | 总控运行下面的命令 |

不属于某张票的窗口（总控、spec、拆票、审计、合并、测试文档）各占一行，这样各行相加是整个功能的用量。

两个可选窗口（规范维护、错误对接）属于整个项目，能独立做事并与总控沟通，所以单独计算：`agent-loop open` 开窗时登记在项目级的记录里（`<任务目录>/.agent-loop/`），`agent-loop ledger` 和 `agent-loop usage` 在功能的表后面按窗口名各列一行，不计入任何功能的合计。

## 开窗和关窗

票的开发、计划、修复窗口用 `agent-loop ticket open <票> --prompt <提示文件>` 开，它建好 worktree 之后调用下面这条开窗命令；不属于某张票的窗口直接用开窗命令。都不直接调用开窗脚本：

```
agent-loop window open --step <环节> --dir <工作目录> --prompt <提示文件> [--ticket <阶段>-<NN>] [--stage <阶段>] [--model <模型编号>]
```

- **环节**：`spec`、`tickets`、`plan`、`dev`、`fix`、`closing`、`audit`、`merge`、`testdoc`、`regress`（回归执行，和 `testdoc` 用同一个模型设置）。命令按环节取参数文件里对应的模型，拼出启动命令；计划环节用 Claude 模型时自动加计划模式。其他名字的环节（例如 `grilling`、`test`）用 `--model` 指定模型，不指定时跟着总控走。
- **输出**：`window: <窗口编号>`、`window-id: <窗口标识>`、`session: <会话 ID>`。把窗口编号记进进展记录的「开窗」那一行。
- **签到**：命令在初始提示最前面加一行签到命令，加好的提示存在 `<功能目录>/ledger/prompts/<窗口编号>.prompt`。窗口三分钟没签到时监视会通知你（[ticket-file-windows.md](ticket-file-windows.md)「窗口有没有开始、还在不在」）。
- **Codex 窗口**：启动命令里带 `-c check_for_update_on_startup=false`，只在这一次启动上关掉版本更新检查，不改用户的全局设置。
- **重复开窗**：同一张票的同一环节已经有窗口开着时，命令拒绝。那个窗口已经结束时先关窗；确实要再开一个（例如返工时原窗口已关）时加 `--again`。
- **没有登记到的窗口**：没指定功能名启动的总控、用户手动开的窗口，用 `agent-loop window register --step <环节> --session <会话 ID>` 补登记。

关窗用 `agent-loop window close <窗口编号|票号>`：关掉窗口，记下关窗时间，并取一次用量。参数文件「自动关窗」取「关闭」时，窗口由用户关，总控在验收后运行 `agent-loop window close <窗口编号|票号> --record-only`：只登记这个窗口的工作已经结束，不动窗口。

## 总控要运行的命令

| 时点 | 命令 |
| --- | --- |
| 一张票合入阶段分支 | `agent-loop ticket merge <票>`，它合入、记完成时间、登记关窗。手工合入的票才单独运行 `agent-loop ledger done <票>` |
| 票回报完成之后被退回重做 | `agent-loop ledger rework <票>` |
| 高风险票的计划被用户要求修改 | `agent-loop ledger plan-revise <票>` |
| 处理完审计结论 | 对每张有问题的票：`agent-loop ledger audit <票> <严重程度>=<数量> ...` |
| 开出修复票 | `agent-loop ledger source <修复票> <来源票>` |
| 阶段结束、功能结束 | `agent-loop ledger snapshot`，再附上 `agent-loop usage <阶段>` 的输出 |
| 记错了 | `agent-loop ledger undo` 撤销最后一条 |

## 怎么算

- **返工**：只算「票回报完成之后被退回重做」，包括总控核对不通过（漏了验收项、测试没过、改了范围外的文件）和合入后测试失败。窗口提请裁决后继续不算返工，它已经算在裁决次数里。
- **计划修改**：高风险票的计划交给用户后，用户要求改，记一次。
- **审计问题**：阶段审计报告里的每条问题，归到引入它的那张票上，按报告里的严重程度分别计数，例如 `agent-loop ledger audit p1-03 阻塞=1 应修=2`。归不到单张票的问题（两张票之间的衔接、spec 本身的缺口）记在阶段名下：`agent-loop ledger audit p1 应修=1`。用户决定不修或推迟的问题照样计数。
- **修复票**：审计后开出的修复票是新的一行，用 `ledger source` 注明它修的是哪张票的问题。它不算原票的返工。阶段审计和单票审计都一样：单票审计（`after-release.md`）开出的修复也是新的修复票，只是在原票的分支上接着改。
- **用量**：输入（含写入缓存的部分）、输出、缓存读取三个数。在票完成、关窗、阶段结束时各取一次并存下，会话记录以后被清理也不影响已经存下的数。

## 什么时候展示

- **平时不展示**。开发过程中总控的回复里只有开窗清单和待办清单的一行统计。
- **阶段结束**（审计的修复票全部合入之后）和**功能结束**时，总控在汇报里附上 `agent-loop usage <阶段>` 输出的按模型汇总。
- **用户想看时**，在终端运行 `agent-loop ledger`（完整的表）、`agent-loop ledger <阶段>`（只看一个阶段）或 `agent-loop usage`（按模型汇总）。

完成标准：每个开出去的窗口在台账里有一行；每张合入的票有完成时间；阶段汇报里有按模型汇总。
