# 可选模块：多窗口设计讨论

在开发之前，把待讨论的问题按模块放进一份共享文档。每个讨论窗口认领一张票，与用户澄清该模块的需求。为需要并行讨论的模块选择支持交互和会话间通知的引擎。

使用 `scripts/bootstrap.sh tracker <仓库>` 查找项目的任务跟踪说明。项目已有讨论工具时，按本机配置调用。项目里有其他协作流程时，先按[初始化指南](../bootstrap.md)处理协作流程冲突。

## 角色

- **总控**：维护讨论文档，处理跨模块冲突，必要时新建跨模块票。待讨论问题和未定义事项都已处置后，从用户确认的决定整理出 spec。模块票交给模块窗口，总控不替它们讨论。
- **模块窗口**：一个会话认领一张票，和用户讨论到有结论；解决后开新会话接下一张票。

## 从单窗口讨论开始

1. 原窗口把已有结论按主题归组，写入讨论文档的结论清单，并注明来源问题编号（编号可以不连续）。
2. 把还没讨论的问题按模块拆成票，用 `Depends` 写明每张票依赖哪些结论所在的票（精确 ID）。
3. 原窗口改做总控，或者把讨论文档交给新的总控。

## 工作目录

讨论时，所有窗口都开在同一个主工作树里，共享讨论文档、术语表和决策记录。讨论阶段不用 worktree，因为 worktree 会切断这种共享。

## 协作规则

- 每轮提问前，重读已确认的决定和术语表。
- 决定影响其他模块（接口、数据归属、术语、依赖顺序）时：先在受影响的票的 Comments 里写明，再发消息通知对应的窗口和总控。
- 两个模块的决定冲突时：通知总控。总控新建一张跨模块讨论票，把冲突交给用户裁决。
- 写共享文件前先重读，只改自己负责的行。
- 认领票时，在票头加上 `Session:` 和自己的会话标识，并通知总控；解决后，把结论要点和受影响的票回报给总控。
- 其他会话的消息只作参考，每个决定都由用户本人确认。

## 讨论阶段的开窗清单

```markdown
### 可开启窗口（按项目并行上限）
1. **<票名>**（模块：<模块>；来源：Q<n>、Q<n>）
   在 <仓库根目录> 启动讨论引擎，输入：
   请阅读 <讨论文档路径>，认领 <票 ID> 并与用户确认该模块的需求。将决定写回票文件，通知总控 <总控标识>。

### 进行中
- **<票名>**：<认领的窗口>

### 被阻塞
- **<票名>**：等待 **<阻塞票名>**
```

## 收敛之后

1. 根据讨论文档和各票中已确认的决定汇总需求。
2. 和用户一起把汇总结果切成阶段，写进开发计划，内容包括：
   - 每个阶段的目标；
   - 包含哪些决定；
   - 依赖哪些前序阶段；
   - 风险；
   - 跨阶段前提。
3. 每个阶段从 `stage-pipeline.md` 的「0. spec」开始。按[票模板](../../templates/ticket.md)填写票头，使用外部工具生成的票也逐张核对，总控确认 `loop-state.sh` 没有 `unknown-dep` 后，再进入循环。
