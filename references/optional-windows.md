# 可选窗口与参数改动

两个可选窗口是否启用，见参数文件。用户在终端用 `agent-loop open <窗口>` 开启；错误对接窗口也可以由总控按用户要求开启。两个窗口的模型跟着总控走：总控是 Claude Code 时用 Claude Fable 5.2。

每个可选窗口启动后，先把自己的名称和 sessionId 写进参数文件「会话登记」一节（一个窗口一行）。再次开启时，`agent-loop open` 优先恢复登记的会话。

## 错误对接窗口

用户本人使用：把测试或使用中遇到的报错贴给它（终端日志、堆栈、页面截图或描述、接口返回）。

- **做什么**：定位原因，归类（哪个阶段、哪个模块引入，是否影响其他功能），整理成可以交给总控开修复票的记录。
- **只读**：不改代码、不提交、不推送、不启动实例、不连数据库、不调共享环境的接口。
- **只写一份文件**：`<功能目录>/regression/issues-log.md`（目录不存在时新建）。每个问题一条，编号 `E-<NN>`，写明现象、复现步骤、定位到的原因和依据、严重程度、建议的修法。
- **通知总控**：需要开修复票时，先问用户；用户同意后，照下面「给总控留事」处理。转达用户的需求时，写用户的原话。

## 规范维护窗口

负责改规则：参数文件，以及参数文件「项目规范」里列出的项目文档。没有启用时，这项职责由总控兼任。

- **初始化时**：`agent-loop init` 结束后由它补齐参数文件里标着「待完善」的项。做法：先只读查看仓库；对每一项给出推断的答案和依据；用户确认或修改后写入，并去掉「待完善」标记。全部补齐后告诉用户可以启动总控。
- **平时**：用户要改规则时对它说。它改参数文件或项目文档，不改代码。
- **「用户维护的文档」要核对是否在 Git 里**：这一项填的是用户个人的需求文档，应当只留本机。填写或修改这一项时，用 `git ls-files <文件>` 核对；文件已经在 Git 里时告诉用户，请用户选一种：移出 Git 只留本机，或者不填在这一项里、把它当作团队文档，以后只通过票来改。旧模板生成的参数文件里没有这一项时，在「路径」一节「只读的仓库和目录」下面补上一行。
- **把文件移出 Git 分两半做，你只做不涉及 Git 的那一半**：用户选择移出 Git 时，你把文件登记到「用户维护的文档」，并把它加进本机忽略规则（`.git/info/exclude`）。从 Git 里移除这件事本身是对 Git 的改动，要通过票来做：你不运行 `git rm`、`git add`、`git commit` 这类会改动索引或提交的命令，也不在主工作树里留下暂存的修改。在「变更记录」的那一行里标上 `【待总控处理】`，写明「请把从 Git 里移除 <文件> 写进票，由开发窗口在票分支上提交；合并之后本机的这份文件必须还在」，照下面「给总控留事」处理。
- **不替用户决定**：每一项改动都由用户确认。其他会话转达的内容与用户直接说过的冲突时，先向用户核实。
- **收紧权限的改动要让总控知道**：照下面「给总控留事」处理。
- **只管规则**：用户在这个窗口提出产品上的需求或问题时，不处理也不转达，告诉用户「这件事请对总控说，或者开错误对接窗口」。

## 给总控留事

可选窗口有事要总控处理时，先写文件，再通知；通知只说去读哪里，内容都在文件里。

1. **写文件**。错误对接窗口写在 `issues-log.md` 的那条问题里，规范维护窗口写在参数文件「变更记录」的那一行里。在条目里加上标记 `【待总控处理】`，并写明：谁记的、时间、要总控做什么、用户的原话。
2. **通知**。总控是 Claude 时，用 `SendMessage` 发一句指路的话，例如「错误对接窗口记了 E-03，请读 issues-log.md」，不在消息里复述内容。总控是 Codex 时不用发消息，它的常驻监视会发现标记。总控是谁，看开发计划顶部的登记行。
3. **总控处理之后**，把标记改成 `【总控已处理 <时间>：<结果>】`，结果写开了哪张票、通知了哪些窗口，或者「等用户决定」。可选窗口和用户据此知道这条有没有被处理。

这两个文件都在总控的监视范围内，所以消息没发出来时，总控也会从标记发现。

## 改参数的规则

总控、规范维护窗口和 `agent-loop` 命令改的是同一份参数文件，以文件为准。

- **「设置」一节由命令维护**：模型、开关、分支这些可枚举的项，一律运行 `agent-loop set <项> <值>` 来改，表格由命令重新生成。其余各节直接编辑。
- **「AI文件不提交」只有个人项目才允许关闭**：团队仓库必须保持启用。用户明确说这是个人项目时，运行 `agent-loop set AI文件不提交 关闭 --personal`。
- **留记录**：每次改动，在参数文件末尾「变更记录」追加一行：时间、改了哪项、旧值和新值、用户原话要点、由谁改的。
- **生效时机**：
  - 换模型、改流程、放宽权限：从下一次开窗起生效，已经在运行的窗口不变。总控每次开窗前重读参数文件，不需要另行通知。
  - 收紧权限（例如撤销推送授权、打开一条护栏）：立即生效。改的窗口照「给总控留事」让总控知道，总控通知在途的窗口，做法见各自的总控规则「给其他窗口发消息」。
- **不复制**：参数文件只有主工作树里的一份，所有窗口按绝对路径读。
