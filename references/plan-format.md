# 计划输出格式

适用于所有提交给用户审批的计划：计划模式（`/plan`、ExitPlanMode），以及用户要求给出的实现计划。

计划依次包含以下三节，每节都要写；某节没有内容时写「无」。

## 计划简介

不超过 5 行：目标、改动范围（模块或文件）、实现步骤要点、验证方式。高风险票还要附测试先行的用例清单，写到具体用例。

## 缺失要素

制定或执行计划所需、但当前缺少的输入，例如需求细节、接口契约、数据样例、权限、环境、上游依赖。每条写明：

- 缺什么；
- 影响计划的哪一步；
- 建议从哪里获取。

需要只读仓库或外部依赖方改动的，作为缺失要素列给用户，计划只在本仓库内实施。

## 待明确 TODO

需要用户做决定的问题，用清单列出：

```markdown
- [ ] <问题> —— 推荐：<推荐答案> —— 未明确前计划的处理：<暂按推荐 / 跳过该步 / 阻塞>
```

高风险票的计划在交用户审批之前，先把这份清单逐项问用户，每项给出推荐答案；用户答完后把结论写进计划正文，清单里只留已有结论的条目（写成 `- [x] <问题> —— 结论：<用户的选择>`）。用户批准的应当是一份没有悬着事项的计划。

完成标准：计划依赖的每一个未经用户确认的假设，都出现在「缺失要素」或「待明确 TODO」中；交审批时，每条 TODO 都有用户的结论。
