# 恢复、异常与交接

状态转换以 `protocol.md` 的状态转换表为准；本文件只说明怎么查现场、怎么选转换。

## 总控启动或恢复时的核对

先 `loopctl acquire` 取得所有权，再运行 `scripts/loop-state.sh <票目录> <可派工的分诊状态>` 和 `scripts/loopctl -r <运行目录> pending`。然后逐张核对非终态的票，以及每个还没有结果的动作：

| `Run` | worker 进程 | 处理 |
| --- | --- | --- |
| `dispatched` | 运行中 | 加入监视，等 worker 开工 |
| `dispatched` | 已退出或没有 pid | 派工中断。先看运行目录里的日志，以及票分支上有没有新提交：有进展就按 T10 接续；没有就清空派工字段，回到 `idle`。不新建 worktree，复用原来的 |
| `claimed` / `planning` | 运行中 | 加入监视 |
| `claimed` / `planning` | 已退出 | 按「异常」处理（T10 / T12） |
| `needs-decision` | 任意 | 还没写裁决的，裁决；已写裁决、但还没有 `Ack` 的，按「送回」处理；送回前先确认 worker 是否还在运行 |
| `done` / `plan-review` | 任意 | 按 `verification.md` 验收 |
| `accepted`，但 `Accepted` 为空 | — | 上次中断在记录之前：用 `loopctl merged-check` 找到合入提交，补写 `Accepted` |

未完成的动作（`loopctl pending`）：

| 动作 | 核对 | 处理 |
| --- | --- | --- |
| `<Run-id>.launch` | pid 文件对应的进程在不在 | 在：`result` 记下 pid，加入监视。不在：看日志和票头，worker 已经开工的按 T10 处理；没开工的，再执行一次 `launch.sh`（进程还在时它会拒绝，所以重复执行是安全的） |
| `<Run-id>.merge` | `loopctl merged-check <仓库> <阶段分支> <票分支>` | 已合入：`result` 记下合入 SHA，补写 `Accepted`，**不再合入**。未合入：重新验收后合入 |
| 推送、发布 | 远端分支上有没有目标提交（`git ls-remote`） | 已推送：记下结果。未推送：重新核对授权和目标后再推送；查不到结果时停下，标为「结果待核实」，交给用户 |

已处理事件文件（`<运行目录>/events-seen`）会保留下来。恢复后重挂监视，不会重复报告已经处理过的事件。如果中断发生在处理事件之后、登记之前，监视会再报一次这个事件。这时先按上表核对现场，确认已经处理过的，直接登记，不重复执行。

核对完成后挂上监视，输出开窗清单。

## 异常

监视报告 `exited` 或 `overdue` 时：

1. **看现场**：运行目录里的日志、票分支上的提交、worktree 中未提交的改动、Comments 最后几块。
2. **按原因选转换**：
   - 做完了但忘了改票头：按 `done` 走验收流程，并在 Comments 写明是由总控代为判定的。
   - 工具崩溃、额度用尽、上下文溢出：同一张票第一次异常时，按 T10 自动重派一次。提示里写明「从已有提交和 Comments 继续」，并写一个 `### 异常` 块。
   - `overdue`，但还在推进：延长 `Deadline`，并写进 Comments（T11）。
   - 卡住或反复出错：转为 `paused`（T12），交给用户。
3. **迟到的回报**：旧的 `Run-id` 写来的回报、提交，留作证据；它们不能覆盖当前运行，也不能用来验收。
4. **worktree 有未提交的工作**：重派时保留现场，由新的 worker 接手；总控不清理、不丢弃。

## 总控交接

验收标准：新的总控会话只靠持久记录，就能重建当前工作。持久记录包括票文件、进展记录、运行目录和交接说明。

出现以下任一情况时交接：一个阶段结束；用户要求交接；总控明显变慢，或者开始遗忘早先的裁决。

1. 写交接说明 `<票目录>/../coordinator-handoff.md`，内容包括：
   - 当前阶段、阶段分支和基点；
   - 每张非终态票的 `Run`、`Run-id`、worker，以及在等什么；
   - 等用户答复的问题；已经做出、但还没写进规则的裁决；
   - 生效中的授权记录和最近的撤权；
   - 监视命令。
2. 停止当前的监视。
3. 请用户开一个新的总控会话，调用本 skill。新总控在启动第 3 步之前，先读这份交接说明。

能压缩上下文的工具，也可以在阶段之间压缩上下文，代替交接。

总控互斥靠 `loopctl` 的代次：新总控 `acquire` 之后，旧总控的任何写入都会因代次不符而失败（退出码 3），旧总控只能读状态。旧总控还在租约内时，新总控取不到所有权，要么等租约过期，要么先停掉旧总控。
