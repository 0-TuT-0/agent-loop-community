# 验收

worker 把 `Run` 改为 `done` 或 `plan-review` 之后，由总控验收。验收通过才写 `accepted`（状态转换表 T9）。总控不审代码，只用仓库和文件里的客观事实，去对照 worker 的回报。

## 共同检查

1. **身份**：完成回报的 `Run-id` 等于票头当前的 `Run-id`。迟到的旧运行回报留作证据，但不能用来验收。
2. **回报完整**：本角色要求的每一项都有内容，或者写了「无」。
3. **外部依赖**：回报里列出需要用户执行的脚本或操作时，给对应的票加上 `External-<ID>: pending blocks=<被阻塞的动作>`，并记进进展记录。`accepted` 可以和 pending 的外部前置同时存在。
4. **生效规则**：在验收时，再核对一次本票生效规则里的授权和验收标准。期间如果发生过撤权，或验收标准有变化（`worker-contract.md`「规则变更的生效时机」），就按新规则验收。

## 按交付类型检查

### `commit`

1. **最终提交**：完成回报里的 HEAD SHA，必须**等于**核对时票分支的 HEAD（`git rev-parse <票分支>`）。被测 SHA 也必须等于这个 HEAD。如果先测了 A 又提交了 B，就不通过。
2. **范围**：`git diff --name-only <基点>...<票分支>` 列出的每个文件，都在 `Touches` 里，或者有裁决批准过。本机专用文件、日志、pid 文件一个都不能出现。
3. **工作区干净**：worktree 执行 `git status --porcelain` 结果为空。pid 和日志都在运行目录里，不在 worktree 中，所以这里不需要豁免。
4. **测试**：
   - 核对方式 `report`（默认）：回报写明测试命令、被测 SHA 和结果。
     - 有回归基准的项目，**逐条比对失败用例的标识**，不只比较数量：没有新增失败才通过。原本失败、现在通过的用例记录下来，交给下一次重建基准时处理。跳过和未运行的用例要单独列出。
     - 没有回归基准的项目，要求全绿。
   - 核对方式 `rerun`：除了核对回报，总控还要在票分支 HEAD 上重跑定向测试。适用于两种情况：参数文件标为低可信的引擎，或者这张票已经返工过。
5. **跨边界**：改动跨越系统边界（接口、序列化格式、文件格式、外部服务）时，回报必须写明样例来源。只靠自造样例让两边测试都通过的，记为「未验证项」，进入环境测试清单。不阻塞本票，但要在进展记录里登记。
6. **集成**：按 `modules/git-worktree.md`「串行集成」，用 `--no-ff` 合入阶段分支，`Accepted` 写集成后的 SHA。合入后，按同一文件「阶段分支前进后」检查在途的票。集成后的结果和票分支不同（例如期间有其他票合入、或者解过冲突）时，按影响范围在集成提交上补跑定向测试。合入冲突时停下交给你。

### `artifact`

1. 产物文件在约定的路径上，最后一个非空行是 `LOOP-DONE <当前 Run-id>`。
2. 产物的 sha256 前 12 位，与完成回报里写的一致。
3. 产物内容符合角色要求，例如审计报告有分级结论和总体结论，基准文件记录了基点 SHA、命令、环境和失败用例标识。
4. 本角色不提交：`git status --porcelain` 中不能出现代码改动。
5. `Accepted` 写成 `<产物路径>@<sha256 前 12 位>`。

### `approved-plan`（包括高风险票的计划前置）

1. 计划文件在 `<阶段目录>/plans/<ID>-plan.md`，开头写有「用户已审定（<日期时间>，<要点>）」。
2. 计划文件的 sha256 前 12 位，与完成回报里写的一致。
3. 把 `Plan` 写成 `<路径>@<sha256 前 12 位>`。
   - `Deliverable: approved-plan` 的票：转为 `accepted`。
   - 只是计划前置的票：转回 `idle`，等待开发派工。
4. 开发 worker 开工时会核对计划的 sha256。计划在审定后又被改过的，要重新请你审定。

## 结果

- **全部通过**：写 `### 核对`（逐项写出检查结果），写 `Accepted`，把 `Run` 改为 `accepted`，然后写进展记录。
- **不通过**：写 `### 核对` 列出问题，按状态转换表 T8 返工；返工后仍不通过的，走 T12。

完成标准：每张 `accepted` 的票，Comments 中都有一条核对记录，上面各项的结果都写明了。
