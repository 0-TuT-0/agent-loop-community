# 开窗清单

总控每次输出计划、进展或票列表时，都在回复末尾附上开窗清单。

1. 重读当前阶段的地图或票目录，以及所有未完成的票。
2. 把每张未完成的票归入一类：
   - **可开启**：所有 `Blocked by` 都已完成，且还没有人认领。
   - **进行中**：已认领，或者窗口已开。
   - **等裁决**：票头是 `Status: needs-decision`。
   - **被阻塞**：至少有一张 `Blocked by` 还没完成，或者在等用户执行 SQL、审定计划。
3. 按下面的模板输出。
4. 在开窗清单后面附一行待办清单的统计（`agent-loop todo --count` 的输出）；清单为空时省略。本次回复里清单有新增或关闭的条目时，在这一行下面各列一行（[todo.md](todo.md)）。

卡着某张票的事写在开窗清单里（「被阻塞」「等裁决」「需要用户做的事」）；不卡任何一张票的事进待办清单，不在这里重复列。

完成标准：每张未完成的票恰好出现一次；被阻塞的票写明在等什么；待办清单非空时有一行统计。

## 讨论阶段（wayfinder 地图）

```markdown
### 可开启窗口（建议同时开 ≤3 个）

1. **<票名>**（模块：<模块>；来源：Q<n>、Q<n>）
   新终端执行：
   cd <仓库根目录>
   claude
   进入后输入：
   /wayfinder <地图路径> 处理"<票名>"这张票。总控会话：<总控当前名称>（sessionId：<id>）

### 进行中
- **<票名>**：<认领窗口名称>

### 被阻塞
- **<票名>**：等待 **<阻塞票名>**
```

所有票都已解决、Not yet specified 也清空时，开窗清单改成一行提示：在总控窗口运行 `/to-spec` 汇总。

## 开发阶段

```markdown
### 可开启（总控将自动开启 / 等用户确认）
1. **<阶段>-<NN> <票名>**（风险：<高/中/低>；执行：<每一步的引擎、具体模型和推理强度，例如「计划 Claude Fable 5.2（计划模式）→ 开发 Codex gpt-6.2-sol（medium）」或「Codex gpt-6.2-sol（medium）」>）

### 进行中
- **<阶段>-<NN>**：<当前这一步的引擎和具体模型>，<窗口名称或会话 ID>，worktree `<路径>`

### 等裁决
- **<阶段>-<NN>**：待裁决 <n> —— <一句话问题> —— <总控可裁 / 需用户决定>

### 被阻塞
- **<阶段>-<NN>**：等待 **<票或事项>**（例如：用户执行 `<SQL 文件>`、用户审定计划）

### 需要用户做的事
- <事项>：<为什么、做完后哪张票可以继续>

待办：遗留 <n> 条（<n> 条建议<时限>处理）、想法 <n> 条
```

开发阶段由总控按「自动接续」自己开窗，所以清单里不写启动命令，只写状态。执行方式一律写到具体模型（含推理强度），模型取自参数文件，不只写「Claude」「Codex」。修复分支上的票和单独开的大需求票也列在这里。没有任何需要用户做的事时，省略最后一节。
